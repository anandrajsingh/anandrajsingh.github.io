React is a javascript library for building user interfaces, especially Single Page Applications. It uses a component-based architecture and Virtual DOM for efficient updates.

<h4>Why It was created</h4>

- Avoid manual DOM manipulation
- Imporve maintianability
- Build scalable UIs

Before React, developers used jQuery/VanillaJS, direct DOM manipulation thus managing UI became messy and error-prone.
Updating real DOM is slow. React creates a virtual DOM(in memory). Compares old vDOM with new vDOM and updates only the changed parts. This process is reconciliation.

<h4>Key Concepts</h4>

- <b>Declarative UI</b> → describe UI, React handles updates
- Component based architecture
- Virtual DOM

<h4>What triggers re-render</h4>

- State change
- Props change
- Parent re-render

<h2>SPA vs MPA</h2>
SPA (Single Page Application)

- Loads once
- Updates UI dynamically
- No full page reload

MPA (Multi Page Application)

- New HTML on every request
- Full page reload

Key differences:
SPA does not have reload it fetches all the files one time and then keeps updating as the data changes thus it is faster after load, on the other hand MPA has rull reload thus slow in navigation

<a> reloads page while <Link> client-side navigation

<h2>JSX</h2>
JSX is a syntax extension for Javascript that looks like HTML

- JSX ≠ HTML
- Compiled by Babel
- Converts to: React.createElement()

<h4>Rules</h4>

- Single parent element
- Use {} for JS
- classname instead of class
- Self-closing tags

<h2>Components</h2>
In React, components are independent UI building blocks. They allow you to split the UI into independent, reusable pieces that can be thought of as custom, self-contained HTML elements.

<h4>Types</h4>

- Functional (modern)
- Class (legacy)

<h4>Difference</h4>

Functional components are modern, simple and use hooks while Class components are legacy, verbose and use lifecycle methods.

<h2>Props</h2>
Props are the way to pass data from one component to another in React.

<h4>Key Points</h4>

- Read-only (immutable)
- One-way data flow
- Used for communication

<h4>Important</h4>

- Mutation is possible in JS but bad practice
- React may freeze props(dev mode)

<h4>Edge Case</h4>
user.name = "Rahul"
This works (object reference) but is bad practice

<h2> State</h2>
Data managed inside component that changes over time

<h4>Key Rules</h4>

- Use useState
- Never mutate directly
- Use setter function

<h4>Behaviour</h4>

- State update triggers re-render
- Updates are asynchronous
- Updates are batched

<h4>Function Update</h4>
setCount(prev => prev + 1)

<h4>Common Mistake</h4>
setCount(count + 1);
setCount(count + 1);
// result = +1 ❌

<h2>Event Handling</h2>
Handling user interactions

<h4>Rules</h4>

- Camelcase (onClick)
- Pass function reference

onClick={handleClick} ✅
onClick={handleClick()} ❌ (runs immediately)

<h4>Synthetic Event</h4>

- React wrapper around native events
- Cross-browser compatible

<h4>preventDefault</h4>
Prevents default browser behaviour (e.g. form reload)


<h2>Conditional Rerendering</h2>
You can render different components or elements based on certain conditions

<h4>Methods</h4>

- Ternary
- &&
- if-else

<h4>Edge Case</h4>
0 && <h1>Hello</h1> → 0


<h2>List & Keys</h2>
Rendering lists using .map()

Keys
- Unique Identifier
- Used for reconciliation

Rules
- Must be unique
- Avoid index as a key

Why index is bad
- Causes incorrect UI update on reorder


<h2>Controlled vs Uncontrolled</h2>

Controlled
- React state controls input

Uncontrolled
- DOM controls input
- Uses useRef

Controlled is predictable and uses React state while Uncontrolled has lesser control and uses DOM 

<h4>Warning</h4>
useState(undefined)
→ uncontrolled → controlled warning



<h2>useState</h2>

Key Concepts
- Async updates
- Batching
- Stale state

<h4>Stale State</h4>
Using outdated values due to closure

<h4>Important</h4>

- Lat update wins
- Functional updates fix issues

<h4>Mutation</h4>
arr.push() ❌
setArr([...arr]) ✅



<h2>useEffect</h2>
Handels side effects

<b>Side Effects</b> are operations that interact with the outside world or have effects beyond the component's rendering. Example include:

- Fetching data from API
- Modifying the DOM manually
- Subscribing to events (like Websocket connections, timers, or browser events)
- Starting a clock

<h4>Dependency Behaviour</h4>

[]      once
[x]     when x changes
none    every rerender


<h4>Cleanup Function</h4>

- Runs before next effect
- Runs on unmount

<h4>Infinite Loop</h4>

useEffect(() => {
  setCount(count + 1);
}, [count])


<h2>useRef</h2>
Stores value without re-render

<h4>Uses</h4>

- Access DOM
- Persist value
- Avoid re-renders

ex: ref.current.focus()


<h2>useContext</h2>
Share data globally without prop drilling

<h4>Key Concepts</h4>

- createContext
- Provider
- useContext

Important Points
- Default value used only if no Provider
- Provider overrides even with undefined

Note: When data is changing frequently, it should not be used as it causes performance issues


<h2>Component Lifecycle</h2>
Different stages that a component goes through

1. Mounting (created)  When Component is created and inserted into DOM
2. Updating (rerender) When props, states change
3. Unmounting (removed) When component is removed from DOM and cleanup is performed

Class Component Lifecycle methods
- componentDidMount()
- componentDidUpdate()
- componentWillUnmount()

In functional component everything is handled by useEffect() hook

<h4>Combined Example</h4>
useEffect(() => {
  console.log("Mounted or Updated");

  return () => {
    console.log("Cleanup (before update/unmount)");
  };
}, [count]);

<h4>Execution Flow</h4>
When count changes:
Cleanup runs before next effect, not just on unmount but also on re-run.

1. Cleanup (old)
2. Run effect (new)
